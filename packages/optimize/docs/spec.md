# spec — dsh-optimize

> この文書が答える問い: **dsh-optimize は何をするべきか**。外部から観測できる振る舞いと契約だけを書き、実装方法は書かない。

## 目的

DeepSeek Harness (DSH) に、小さな改善・調整をまとめて提供する。対象は Web GUI の見た目や操作に限らず、
セッションの振る舞い、ツール、コマンドなどの Host 側の挙動も含む。
利用者は設定タブで機能ごとに有効・無効を選べる。有効にした機能だけが DSH に影響する。

## 用語

- **機能 (feature)**: 単一の改善。1つの識別子、1つの真偽設定を持ち、Host 側・Client 側・その両方の
  いずれかで実装される。
- **面 (side)**: 機能が作用する実行環境。`host` は DSH の Node プロセス、`client` はブラウザ。
- **設定タブ**: Settings パネルのナビゲーションに追加される `Optimization` セクション。
- **設定ドキュメント**: DSH が profile ごとに保持するプラグイン設定。本プラグインは `optimize` 名前空間を使う。
- **有効/無効**: 機能の真偽設定。無効は「追加の効果が一切ない」状態を意味する。
- **反映方式**: トグルを変えたときに効果が現れる時機。即時反映と再起動反映の2種がある。

## 契約

### S1 設定タブ

- Settings パネルのナビゲーションに `Optimization` が1項目表示される。
- 選択すると設定ページが開き、機能一覧が表示される。機能がまだ無いときは、空であることを示す文言を表示する。
- ナビゲーション項目にはアイコンが表示される（シェル既定のアイコンでよい）。
- Host 側が構成に含まれない場合、タブは表示されない（ページだけが残る状態にならない）。

### S2 機能トグル

- 機能ごとに独立した ON/OFF を持つ。1機能の状態が他の機能の状態に影響しない。
- すべての機能の既定値は OFF。
- OFF の機能は、見た目にも挙動にも影響しない。作用する面が Host でも Client でも同じ。
- 機能一覧の各行は、機能名・説明・現在の状態・操作手段を示す。
- 機能一覧の各行は、作用する面（Host / Client / 両方）と反映方式（即時 / 再起動）を示す。
- 全機能の一括 ON、一括 OFF、初期値（すべて OFF）への復帰ができる。
  ただし再起動反映の機能は、一括操作の直後には効果が現れない。
- 機能一覧を名前と説明で絞り込める。

### S3 反映

- トグル操作に保存操作を要求せず、即時に反映される。
- 反映にページの再読み込みやセッションの再開を要求しない。
- 無効化は即時に効果を打ち消す。スタイル、スロットへの寄与、イベント購読、Host 側の登録が残らない。
- 即時反映できない機能は、設定タブの行に「DSH の再起動が必要」と表示する。
  その機能のトグルは値を保存するだけで、効果は次回の DSH 起動時に現れる。
- 再起動反映の機能も、無効のまま起動した場合は何の効果も持たない。

### S4 永続化

- 状態はプラグイン独自のストレージではなく DSH の設定ドキュメントに保存される。
- ページ再読み込み、DSH 再起動の後も状態が保持される。
- 状態は profile の設定ファイルとして利用者が直接確認・編集できる。

### S5 書込不能時

- 設定ドキュメントが読み取り専用のとき、すべてのトグルが無効化され、その理由が画面に示される。
- Host が `optimize` 名前空間を配信していない場合、タブは現れない。

### S6 失敗隔離

- 1つの機能の初期化に失敗しても、他の機能と設定ページは動作を継続する。
- 機能の失敗はログに残る。面をまたぐ機能では、片側の失敗がもう片側を止めない。
- トグル操作の書き込みに失敗した場合、画面には現在の状態が再表示され、利用者は再試行できる。

### S7 対象バージョン

- 期待する DSH バージョン以外で動作した場合、起動時に警告がログに残る。機能は引き続き試行する。
- 期待バージョンと、その確認方法は `development.md` に従う。

### S8 表示言語

- 設定タブが表示する文言は英語のみ。

## 機能仕様の記述形式

個々の機能の仕様は、この節に1機能1小節で追記する。各小節は次を含む。

- **識別子**: 設定キー（camelCase）、表示名、既定値（OFF 固定）
- **作用する面**: `host` / `client` / 両方
- **反映方式**: 即時 / 再起動
- **有効時の変化**: 利用者が観測できる変化（見た目・操作・出力・振る舞い）
- **無効時の復元**: 打ち消される副作用（スタイル、登録、購読、Host 側の提供）
- **前提と制約**: 依存する DSH の契約、他機能・他プラグインとの排他

## 非目標

- 設定シェル、レイアウト、テーマの置き換え。既存 UI の描画自体の差し替え。
- 既存設定項目の代替・再実装。
- 他プラグインの設定名前空間やファイルの書き換え。DSH 本体のファイル改変。
- プラグイン独自の設定ストレージ。
- 多言語 UI。既定値の自動有効化。
- 外部通信、テレメトリ、更新確認。
